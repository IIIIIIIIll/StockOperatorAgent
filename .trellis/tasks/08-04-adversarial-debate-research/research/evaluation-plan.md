# Research: 对抗性会话评估方案（AC3）

- **Query**: RQ3（PRD 08-04-adversarial-debate-research）——无金标场景下如何衡量"对抗性会话增强了没有"：评估信号（最终决策对后续行情方向命中、LLM-as-judge 观点质量、论据覆盖/数量等可解析指标），哪些在本项目数据与架构下可落地、成本几何、判定阈值，哪些依赖未来数据积累。
- **Scope**: internal（本项目事实，带 file:line）+ 文献（ddgs 检索 2026-08-04）+ 统计常识
- **Date**: 2026-08-04

## 0. 总体设计：配对 A/B，差分评估

- 同一股票、同一图、同一输入上下文，跑**两臂**：对抗会话关（基线） vs 开（方案 4/3/1，见 AC2）。配对比较，消除个股/时段系统性偏差。
- 关键优势（本项目特有）：两臂共用完全相同的 `stock_information` 上下文与历史数据——即使回放有 lookahead 污染（见 §1.3），**污染对两臂等量**，相对差分结论仍然有效；绝对命中率则有上偏风险，须如实标注。
- 评估运行建议 `WEB_SEARCH_DISABLED`（开关语义见 agents spec / `core/investment_committee.py:71`）：
  1. 控成本（每节点工具轮 ≤10，`core/llms/tool_loop.py:29`，评估批量跑会烧掉搜索配额）；
  2. 消除"搜索内容不同"这一两臂之外的混入变量。
- 每个信号给出：所需数据、成本/轮、判定阈值、未来数据依赖。

## 1. 数据就绪度（本项目事实，2026-08-04 实测）

### 1.1 有：日K 全历史（可 as-of 截断）

- ZODB `ChinaStockData`（date/open/high/low/close/volume/换手率，前复权链路 `adjust.qfq_adjust`）逐日存储（`data_structure/chinese_mainland/ChinaStockData.py`；`ChinaStock.add_datas` 按 `date > last_data_update` 去重追加，`data_structure/chinese_mainland/ChinaStock.py`）。
- 【实测】600519：5973 根 bar、5973 个唯一日期，2001-08-27 → 2026-07-31，25 年完整历史——**长窗口回放数据可行**。
- 【实测】**000001 数据被污染**：4385 行但仅 122 个唯一日期（2026-01-30 → 2026-08-04），89 个日期重复（疑似测试播种残留）——回放前必须按 date 去重，且**只用唯一日期采样**。
- 【实测】库内 21 只股票、仅 10 只有行情数据——**多股票样本池当前很小**（见 §7）。
- 技术指标可 as-of 重算：`compute_all` 输入就是 DataFrame（`core/llms/tools/get_trend_indicators.py:37-53`），研究脚本可对截断到 T 的 bars 直接构造帧重算（不调工具、不动产品代码）。
- formatter 的"Last 60 days prices / Last 20 financial abstracts"（`core/stock_output_formatter.py:21-31`）是相对当前库的切片——把 stock.datas 截断到 T 后再走 formatter 即得 as-of 切片。

### 1.2 部分有：业绩报告（点时间、可过滤）

- ZODB `performance_reports` 是追加式点时间序列（`report_date` 递增去重，`ChinaStock.py add_performance_reports`）——按 `report_date ≤ T` 过滤即得 T 时点已知信息。【实测】000001 有 9 份报告。

### 1.3 无（回放 lookahead 污染源，必须标注）

- **overview 只存最新快照**：`latest price / PE / PB / momentum`（`core/stock_output_formatter.py:14-20`）无历史版本——回放到历史日期 T 时喂给 LLM 的是"今天的"估值，属未来信息。
- **财务指标实时拉取**：`get_financial_indicators` 走 TDX 网络且只取 `period.max()` 最新期（`core/llms/tools/get_financial_indicators.py:23-44,42-43`）——非点时间，回放时是"现在的最新季度"。
- **实时情报实时拉取**：`get_market_intel`（TDX MCP，`core/investment_committee.py:19-49`）无历史——回放只能降级占位（与生产上下文不一致）。
- 推论：严格"历史快照回放"需在 research/ 内新写 as-of context 构造器（截断 bars + 过滤报告 + 重算指标 + 占位情报），**overview 与财务指标的 lookahead 无法消除**。因此：
  - 绝对命中率报告须附"含 lookahead 上偏"声明；
  - **主判据用 A/B 差分**（两臂同污染，抵消）。

### 1.4 交易日历

- 现有 `get_last_business_day` 是纯 weekday 近似、无节假日表（`utils/time_helper.py:15-28`）——**回放选点不要用它**；直接用 ZODB 里的实际 bar 日期列表（真实交易日）采样 T，前向窗口 = 后续 H 根实际 bar。

## 2. 信号 1：最终决策 vs 后续行情方向

### 2.1 设计

- 每个样本 =（股票, 日期 T, 臂）→ 跑完整图 → 得 `final_decision`（自由文本：短中长期操作建议 + 信心度，`core/llms/prompt.py:124-129`）→ 解析为方向（看多/中性/看空）→ 与 T 后 H 根 bar 的实际收益符号比对（H ∈ {5, 20, 60} 交易日，分别对短/中/长期建议）。
- 方向解析：规则（买入/加仓/增持/卖出/减仓/回避 关键词 + 目标价 vs T 收盘价）优先，兜底 +1 次 LLM 分类调用/样本（或复用 manager 的百分比信心度）。
- 调仓视角（本项目约束）：A 股 T+1、零售基本无做空——**看空建议只映射为"回避/减仓"**，命中定义 = 看多建议 ∧ 正收益（做对），看空建议 ∧ 负收益或横盘（回避成功），中性 ∧ |收益| < 阈值。
- 样本日期窗：T ≤ now − H（保证前向窗口完整）——即只评估历史日期，**当期及近 H 根 bar 内的日期不可评估**。

### 2.2 所需数据与成本

- 数据：ZODB bars（去重后）+ as-of context 构造器（§1.3，research 脚本）+ 方向解析器。无网络拉取（历史数据已入库；freshness 门对历史日期不会触发重拉——拉取以 `last_data_update` 为界，`ChinaStock.py add_datas`）。
- 成本/样本：图运行 LLM 调用 = 基线 5 / 开臂 7（方案 3，见 AC2 §3）≈ 每次 0.03–0.3 元（量级假设，§6）；无 web_search（评估禁用）。
- 单轮评估（如 20 股 × 20 日 × 2 臂 = 800 次图运行，其中闭臂 400×5 调用 + 开臂 400×7 调用 ≈ 4800 次 LLM 调用）≈ **50–250 元量级**（deepseek-v4-flash 假设单价，§6）+ 约 1.5–2.5 小时墙钟（串行跑，6–10s/次）。

### 2.3 判定阈值

- 增强判定：开启臂方向命中率 ≥ 关闭臂 +**5 个百分点**，且开启臂绝对命中 ≥ 55%（高于随机 50% 才说明系统本身有意义）。
- 样本量（统计常识，配对 McNemar 检验口径）：n=30 只能检出 ~15pp 级差异；5–10pp 级差异需 **n≥50–100**。因此信号 1 的结论按样本量分级报告（"检出/未检出/样本不足"）。
- 前瞻窗口按 H 分层分别报告（短/中/长期命中率），不做单一合计数。

### 2.4 未来数据依赖

- 前向收益：需要 T 之后 H 根 bar 已存在 → 评估日期永远滞后于当前 H 根 bar（**随时间自然积累**）；
- 多股票样本：当前仅 10 只有 bar（实测）——扩充需 TDX 拉取（网络+存储成本，无 LLM 成本，`fetch_daily` 链路现成）或随日常使用积累；
- 该信号**不可立即大规模执行**，属中期信号。

## 3. 信号 2：LLM-as-judge 观点质量对比

### 3.1 设计

- 同股同图跑两臂 → 各得（bullish 观点, bearish 观点, final_decision）→ 独立 judge（研究脚本内新 prompt，不进产品）按维度 10 分制评分：论据完整性、内部一致性、对反方论据的回应强度（开臂特有维度，闭臂计 0 分或单列）、数据引用规范性、表述清晰度。
- 抗偏差设计（文献：Zheng et al. 2023，arxiv 2306.05685——位置偏差/冗长偏差/自偏好）：
  - **交换呈现顺序**：同一样本 judge 两次，A 先/B 先，取平均；
  - **按维度打分**而非整体偏好，长度影响降到最低（开臂文本更长，整体偏好会被冗长偏差污染）；
  - **3 次重复多数决**抗 judge 自身方差；固定 seed（`DeepSeekApi` 默认 `seed=114514`，见 agents spec LLM 配置段）；
  - judge 与 trader 同模型存在自偏好风险——可换 `deepseek-v4-pro`（`DEEPSEEK_MODEL` 可切）或独立 judge prompt 缓解。

### 3.2 所需数据与成本

- 数据：仅两臂输出文本 + judge prompt——**无历史数据依赖，立即可跑**。
- 成本/样本：图运行（同信号 1，0.03–0.3 元）+ judge 2×3 次调用（顺序交换 × 3 重复，每次 0.02–0.1 元）→ **单样本合计 ≈ 0.2–1.2 元量级**（两臂 + judge）。
- 单轮评估（30 样本配对：两臂图运行 30×(5+7)=360 次调用 + judge 30×2×6=360 次调用，共 ≈720 次 LLM 调用）≈ **10–50 元量级**。

### 3.3 判定阈值

- 主判据：开臂在"对反方论据的回应强度"与"论据完整性"两维均分 ≥ 闭臂 +0.5 分（10 分制，配对）；整体胜率（多数决后逐样本胜负）≥ **60%**（n≥20）。
- 辅助：judge 一致性报告（3 次重复的一致率，<60% 则该样本判定作废重评）。

### 3.4 未来数据依赖

- 无——**推荐作为首个上线信号**（快速迭代，与实现同周可出结果）。

## 4. 信号 3：可解析论据指标（辅助护栏，不作主判据）

### 4.1 指标与可行性

| 指标 | 解析方式 | 可行性 |
|---|---|---|
| 论据条数（prompt 要求"包含但不限于 5 条"，`prompt.py:74,98`） | 消息文本数要点（正则/计数） | **高**（纯解析，零 LLM） |
| 标注出处的数字数（"必须标明出处"，`prompt.py:78,102`） | 同上 | 高 |
| 每节点搜索调用数 | 数 `AIMessage.tool_calls` / `ToolMessage`（`core/llms/tool_loop.py:57-79` 追加进 messages 通道，`utils/state.py:8` add_messages 可解析） | 高 |
| 修订保留率（方案 3 草稿→修订版论据重叠率） | 草稿/修订版要点集合交并比 | 中（中文要点对齐有噪声） |
| 引用真实性抽查 | 观点中的数字须能在 `stock_information` 上下文找到（全部数据真实提供，`prompt.py:2,9`） | 中（小样本人工/LLM 抽查） |
| **"质量相关性"** | — | **低**（计数≠质量，常识判断）——定位为防退化护栏：开臂不得少于闭臂 |

### 4.2 成本

- ≈ 0（解析零 LLM；抽查另计每次 0.02–0.1 元）。

### 4.3 判定阈值（护栏式）

- 开臂论据条数 ≥ 闭臂（不退化）；
- 修订保留率 ≥ 80%（防 flip-flop 删论据；低于即告警并检查修订 prompt）；
- 引用抽查错误率 ≤ 10%。

## 5. 判定阈值汇总

| 信号 | 主判据 | 阈值 | 最小样本 | 可立即执行 |
|---|---|---|---|---|
| 1 方向命中 | 差分命中率 + 绝对命中 | 开−闭 ≥ +5pp 且开 ≥ 55% | 50–100 | 否（等前向窗口/扩样本池） |
| 2 LLM-judge | 胜率 / 维度均分差 | 胜率 ≥ 60% 或均分差 ≥ +0.5 | 20–30 | **是** |
| 3 解析指标 | 护栏 | 不退化 + 保留率 ≥ 80% | 全量 | 是 |

决策规则（建议）：信号 2 + 3 通过 → 保留该形态并进入信号 1 的积累期；信号 1 累积到 n≥50 后再做最终取舍。

## 6. 成本估算（量级口径）

- 【假设，未在本会话核实】deepseek-v4-flash 单价按 deepseek 系公开量级估：输入 ≈ ¥1–2/M tokens，输出 ≈ ¥5–10/M tokens（2025 年公开 deepseek-chat 档近似；`DEEPSEEK_MODEL` 默认 `deepseek-v4-flash`，可切 pro——见 agents spec LLM 配置段）。
- 单次节点调用 ≈ 2–6K 输入 / 1–3K 输出 → **0.01–0.05 元**；单次图运行（基线 5 调用，无搜索）≈ **0.05–0.25 元**；开臂（方案 3：7 调用）≈ **0.07–0.35 元**（+2 调用 ≈ +0.02–0.1 元）。
- 单轮评估总成本：信号 2（30 样本 ≈ 720 次调用）≈ **10–50 元量级**；信号 1（800 次图运行 ≈ 4800 次调用）≈ **50–250 元量级**。
- 墙钟：一次图运行 ≈ 6–10s（基线 3 阶段 / 开臂 4 阶段，见 AC2；工具禁用时无网络等待）→ 800 次串行 ≈ 1.5–2.5 小时；可并行化（多进程，注意 ZODB flock 不可重入——`get_zodb_storage` 进程级单例，见 core spec；评估脚本**只读**也应每进程独立开库并避免与 app/全量回归并发）。
- 数据层成本：ZODB 本地读 ≈ 0；TDX 拉取仅扩样本池时需要（网络，无 LLM 成本）。
