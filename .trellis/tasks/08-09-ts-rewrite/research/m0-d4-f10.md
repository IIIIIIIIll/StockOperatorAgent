# M0-D4：F10 数据源 + 解析器移植验证

**结论：F10 拉取走 pytdx TCP 命令（非 HTTP）——node-tdx-market 内置
`CompanyCategory(719)` / `CompanyContent(720)` 枚举，继承 `sendCommand`
即可。TS 解析器移植与 Python `f10_parser.py` 输出逐字段一致。**

## 传输层事实（修正早期假设）

- F10 不是 HTTP 文本区间——是 pytdx **TCP 命令** `get_company_info_category`
  (0x2cf) / `get_company_info_content` (0x2d0)。node 库 CommandType 恰好内置。
- **data 段**（移植 pytdx setParams）：
  - Category：`market(u16) + code(6) + 0(u32)` = 12 字节；
    响应 `num(u16)` + 每条 152 字节 `name(64s)+filename(80s)+start(u32)+length(u32)`，GBK。
  - Content：`market(u16) + code(6) + 0(u16) + filename(80s) + start(u32) + length(u32) + 0(u32)` = 102 字节；
    响应：跳过 12 字节 → `length(u16)` → 正文 GBK 解码。
- 实测：600036 拉取成功——16 个分类，【财务分析】节（600036.txt, start=26252, len=44427）
  → 24k 字符文本。

## 关键发现：F10 文本格式依赖服务器/数据源（双格式）

| 维度 | 通达信格式（本次拉取，124.71.187.122） | 港澳资讯格式（项目缓存 300750 等） |
|---|---|---|
| 来源标注 | `◇通达信沪深京F10◇` | `◇港澳资讯 灵通V9.0◇` |
| 分隔符 | `│`（U+2502 制表竖线） | `｜`（U+FF5C 全角竖线） |
| 分节名 | `【1.主要财务指标】`（带编号） | `【1.财务指标】` 下另有 `【主要财务指标】` 无编号 |

项目 `f10_parser.py` 硬编码 U+FF5C + `【主要财务指标】` 精确匹配——
**对通达信格式会解析失败**（现存缺陷，取决于连接服务器）；TS 解析器应做
双格式兼容（分隔符二选一 + 分节名模糊含匹配），列入 M1。
